Three ways to rebuild the panel so nothing can overlap

The overlaps are not styling accidents — nine of them come from the same root cause: rows placed with SameLine(ctx, x) at hand-counted pixel offsets, and a label column measured one frame late that keeps an 84 px floor whenever ReaImGui answers 0 for a glyph it has not rasterized yet. Each mockup below removes that mechanism instead of nudging the numbers.

01

What was overlapping, and what fixed it

Ordered by how visible the collision was. Every one is a hard-coded position or an unguarded measurement, and every one is now fixed in the panel — the section after this is the rule set that replaced them.

F1fixed Fit-preview ruler labels print on top of each other Dub_Pipeline_Panel.lua:8078, 8121

V5.strip_step chooses a tick every 1–600 s so that at most 12 ticks fit — by time, with no reference to pixel width. Each m:ss label is ~30 px, so 12 ticks need ~360 px, but the only guard is if w < 80 then return end. Between 80 and ~380 px of strip width the ruler is unreadable — labels overprint their neighbours.

F2fixed Input boxes drawn on top of their own labels Dub_Pipeline_Panel.lua:1662–1684

V5.label ends with SameLine(ctx, cell_x + form_w), where form_w was measured on the previous frame. ImGui's absolute SameLine sets the cursor to that x whether it is ahead of the label or behind it — so any frame where the label is wider than form_w, the field is drawn straight through the label text. That happens on the first frame of every pane, and permanently whenever ImGui_CalcTextSize returns 0 (ReaImGui does this for glyphs the atlas has not baked — i.e. every non-ASCII label), because the code deliberately keeps the 84 px floor in that case.

F3fixed History state chip overlaps the Import button Dub_Pipeline_Panel.lua:5191–5193

V5.pill is as wide as its text plus 14 px, but the button after it is placed at a fixed x_act + 84. The "your script" chip measures ~85–92 px at the panel's 14 px face, so it runs under the blue Import button on every pasted-script row.

F4fixed History filename prints over the timestamp Dub_Pipeline_Panel.lua:4996, 5164–5172

The filename column is a fixed x0 + 106, leaving 90 px for the date. V5.hist_when normally shortens to "19 Aug 14:32" (~84 px — already marginal) but falls back to the raw stamp "2026-08-19 14:32:07" (~130 px) for legacy or hand-edited tts_history.json entries. The absolute SameLine then walks the cursor backwards and the filename lands on the date.

F5fixed A wide label pushes its field into the next grid column Dub_Pipeline_Panel.lua:2061–2066

V5.cell_field computes grid_w − form_w − reserve and then clamps with math.max(60, …). The clamp protects the field and sacrifices the boundary: with a measured label near LABEL_W_MAX (240) in a CELL_MIN (300) cell and a 46 px reserve, the field's right edge lands 46 px past the cell — through the 20 px CELL_GAP and into the neighbouring cell's label.

F6fixed Script-box counter escapes the right edge Dub_Pipeline_Panel.lua:4696–4702

This is the one right-alignment in the panel that calls ImGui_CalcTextSize raw instead of the zero-guarded V5.text_w. The measured string contains · (U+00B7); a 0 answer puts stats_x exactly on the right edge, so "3 paragraphs · 1,847 characters" is drawn off the pane and clipped by the border.

F7fixed Review toolbar cannot reflow, so it clips Dub_Pipeline_Panel.lua:7831–7960

Five fixed-width buttons chained with SameLine — 130+130+130+125+115 ≈ 660 px, and the action row below is 550 px. There is no wrap and no measured fallback, so a panel narrower than that cuts ⟲ Reload file and Back to setup in half rather than moving them to a second line.

F8fixed Review boxes are three times too tall for Indic text Dub_Pipeline_Panel.lua:7805–7809

_para_box_height divides #string — a byte count — by 90 to guess line count. Devanagari and Bengali run three bytes per character, so every paragraph saturates the 10-line cap and the review grid becomes a column of identical oversized boxes with the text stranded at the top of each.

F9fixed Run-plan value column is a hand-counted 96 px Dub_Pipeline_Panel.lua:9713–9714, 9780

V5.PLAN_VALUE = 96 is the only thing keeping step labels off their values. It survives today because "Transcribe" is 78 px at V5.UI_PX = 14. Raise the UI size, translate a label, or add a longer step name and the value column is overprinted — the same class as F2 and F4, just not triggered yet.

02

The layout contract, as shipped

This is what went into the panel. It is short, and it is what makes F1–F9 unwritable rather than merely fixed — the three mockups below are drawn against the same rules.

No absolute SameLine(ctx, x)

Any row with more than one column becomes a BeginTable with WidthFixed / WidthStretch columns. ImGui sizes them; nothing can be placed behind something already drawn.

removes F1 F3 F4 F9

Labels sit above fields, not beside them

A label and its input never share a row, so a mis-measured label column cannot exist. It also lets Devanagari and Bengali labels take the width they need without stealing it from the field.

removes F2 F5

Every measurement is guarded once

V5.text_w is the only text-measuring call site; it already falls back to a per-character estimate when ReaImGui answers 0. Raw CalcTextSize is banned outside it.

removes F6

Density is derived from pixels, not from time

Tick count is floor(usable / (label_w + 12)), then snapped to the nearest nice step. A strip too narrow for two labels shows none and keeps the bars.

removes F1

Toolbars wrap; they never clip

Button rows are measured and broken onto a second line, and secondary actions collapse into one ⋯ menu below a threshold. Character counts are computed on UTF-8 clusters, never bytes.

removes F7 F8

Truncation is a visible decision

Anything that can outgrow its column ends in a real ellipsis with the full value on hover — filenames, model ids, voice names, chunk text.

removes F3 F4

06

What went into the panel

Every entry is a named function, so it is greppable. The primitives are new; the rest are call sites that stopped counting pixels by hand.

V5.text_w — the only text measurement
Never answers 0. V5.label uses it to measure the label this frame and takes max(column, this label), so a wide label pushes its own control right instead of having it drawn through. The last raw CalcTextSize call outside it is gone.
V5.room / V5.fit_w — how much space there actually is
An explicit pixel width is clamped to the room left on the row, and the room stops at the grid cell's right edge — ImGui's own content region measures to the window and knows nothing about the panel's cells.
V5.wrap_begin / V5.wrap_next — rows that wrap
A button row that does not fit breaks onto a second line and returns to the x the row started at, not the window's margin. Used by V5.segmented, the review toolbar and the prompt editor's footer.
V5.cell — placed at the row's top
The cursor is set to (cell_x, row_top) rather than walked back with SameLine, which returns to the last item's line — the same thing as the row's top only while every cell is one line tall, which stopped being true the moment cells could wrap.
V5.hist_row — measured columns and a forward-only pen
Laid out from the right edge inwards. Every column asks for its x and gets max(that, pen + gap); the two right-hand columns are pinned so they cannot be pushed off the row. The date is ellipsized like everything else.
V5.strip_step — density budgeted in pixels
Asks how many m:ss labels the width holds, not how many fit the duration, and returns "no labels" when the answer is under two.
V5.ellipsize — truncates for any budget
Cuts on a character boundary at both ends and honours small budgets. It used to return the text untouched below 40 px — turning "no room" into "draw all of it" — and could split a character off the tail, which ImGui renders as a hollow box.
V5.cells — lengths in clusters, never bytes
_para_box_height and the two character counters. A Devanagari paragraph is a third as long as # claims.
V5.fld / V5.fgrid — the stacked field
The label above its control, in a grid that pairs short ones two-up and drops to one column when the width cannot hold two. This is what retires the label column: a label and its control cannot collide when they never share a row.
V5.pipe_rail / V5.pipe_card — the pipeline as chrome
Six cards, as many columns as the width holds and the rest wrapped, each carrying its stage's value and the live one its own progress hairline. Replaces a 288 px column that carried the same information in the narrowest space on the screen.
V5.plan_view / V5.plan_table / V5.plan_inspector
A sorted view of the chunks — never sorting P.rows, whose order is the timeline's — a table that shows each chunk's text, and an inspector for the selected one. Worst fit first by default.
V5.commands / V5.pal_draw — the Ctrl-K palette
Every action in the panel by name, as data with a when guard each, so a command this run cannot do is not offered rather than offered and dead. Subsequence matching, so gtl finds "Go to Log", with a word-start match outranking a scattered one. The chosen command runs after the window's Begin/End pair closes — several of them change the phase or launch the engine, and doing that mid-frame loses the frame.
V5.cost_meter — the estimate, split by what spends it
TTS, transcription, headroom. Only the TTS share changes when you shorten the script, so a single total was the one shape that could not inform the decision. On the running screen it says plainly that it is an estimate and not a live total, because the engine does not report credits while it works.
auto_sync_pipeline.lua — the same three, fixed there too
The Sync tab carried a verbatim copy of the counter bug, a flat 104 px label column, and a readiness dot pinned at windowWidth − 38 that could land inside the header text it followed. It has its own _ui_text_w and _ui_ellipsize now.

How it is verified

A harness at dubbing/reaper/layout-harness/ loads both files and draws them — no REAPER, no ReaImGui — recording a rectangle for every item and every DrawList_AddText. A rectangle landing on one already recorded is a failure. Every screen, pane and phase is drawn at eleven widths under three CalcTextSize regimes, plus an old-ReaImGui build with the optional calls absent.

The two standards it holds to

Collisions are never acceptable, at any width — overprinted text is unreadable, and it is what all nine defects produced. Clipping is a failure at or above 560 px, the panel's design floor (a 138 px rail, a usable form, and the 288 px run column). Dragged narrower than that the panel degrades, but it still never draws one thing over another.

The palette, in one paragraph

Every action in this panel lives on exactly one screen, which is right for finding them and wrong for repeating them: opening the log while a run is out means leaving the screen that shows the run. Ctrl-K (⌘K on macOS, via ImGui_Mod_Shortcut) is the second route: 36 commands — 22 written out plus one per rail destination, settings pane and chunk sort — nearly all guarded, filtered by subsequence, driven by the arrow keys and Enter. It is also what lets a toolbar stop growing: the five-button review row existed because there was nowhere else to put a fifth action. It is not an ImGui popup — the panel opens none anywhere, and a palette wants the window dimmed behind it, which is a draw-list rectangle over the content.

Two traps the build turned up

Both are written into the primitives now, not into the call sites. A pending SetNextItemWidth belongs to the next widget only — so a stacked field's "fill the cell" width was eaten by the first button of the segmented row under it, which then filled the cell alone and pushed the second segment clean out of it. V5.segmented and V5.chip size themselves now. And after a caption's line ends, ImGui puts the cursor at the window's left margin, which inside a grid cell is not the cell's left edge — so the control under the caption was drawn against the neighbouring column.

A third is a rule rather than a bug, and it came up twice: never size a container from a per-part budget when one of the parts can flex. The plan transport bar's height was a V5.mh measurement and oscillated — tall canvas → short reserve → short canvas → tall reserve, forever — so it is a fixed constant with a one-line ellipsized note. The palette card was the same mistake from the other direction: computing its height from query row + list + footer needed every part guessed right, and a footer reserve 7 px short made it overflow its own content on every draw. The list is the flexible part now, so any arithmetic error becomes empty space instead of a defect.
